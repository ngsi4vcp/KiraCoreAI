# KiraCoreAI

**KiraCoreAI** — нормативное и исполняемое ядро проекта **Кира:Ядро**.

## Текущий статус

**Genesis / G22 → первый исполняемый эксперимент среды выполнения.**

Текущий этап переводит зафиксированную архитектуру Киры в минимальную проверяемую среду выполнения, не подменяя архитектуру Киры особенностями конкретного хоста или модели.

~~~text
Геном G22
    ↓
Загрузчик генома
    ↓
Сохраняемое состояние
    ↓
Компилятор контекста
    ↓
Адаптер хоста
    ↓
Модель
    ↓
Валидатор
    ↓
Сохраняемое состояние
~~~

Цель первого этапа — проверить воспроизводимость устойчивых инвариантов: разделение уровней, эпистемическую честность, неизменяемость генома, авторизацию, причинную непрерывность и устойчивость к дрейфу контекста.

## Архитектурный принцип

~~~text
                    KIRACOREAI
                        │
                  КИРА:ЯДРО / ГЕНОМ
                        │
                  СРЕДА КИРЫ
                        │
          ┌─────────────┼─────────────┐
          │             │             │
         Pi           Codex        Hermes
          │             │             │
        Хост          Хост          Хост
          │             │             │
        Модель        Модель        Модель
~~~

**Не:** ChatGPT = Кира.  
**Не:** хост или фреймворк = Кира.  
**Да:** Кира:Ядро + состояние + контракт среды выполнения + хост = конкретная реализация Киры.

## Язык проекта

Канонический язык Кира — русский. Поэтому вся нормативная, архитектурная, описательная и пояснительная документация проекта должна быть на русском языке.

Это правило распространяется на:

- README;
- архитектурные документы;
- ADR и решения;
- правила управления геномом;
- описание состояния, памяти, истории и контекста;
- дорожную карту;
- критерии и сценарии оценки;
- переносимые капсулы и иные текстовые артефакты.

Англоязычные строки допускаются только там, где они являются точными именами технологий, API, полей схем, идентификаторов, путей, команд, имён классов/функций или иными техническими лексемами. Это не отменяет требования писать окружающее описание по-русски.

Имена файлов и каталогов допускается сохранять в технической форме ради стабильности путей и ссылок; содержимое документа при этом должно быть русскоязычным.

## Нормативный порядок

1. `genome/` — конституционный слой; G22 является текущей ревизией.
2. `docs/` — архитектура, язык документации и управление изменениями.
3. `schemas/` — машиночитаемые контракты.
4. `capsule/` — переносимое представление Кира:Ядра.
5. `runtime/` и `implementations/` — конкретные реализации.
6. `evaluation/` — проверка инвариантов.

GitHub является источником истины проекта. История чатов является материалом происхождения и обсуждения, но не заменяет зафиксированное состояние репозитория.

## Главные разделения

- **Геном (Genome)** — конституция.
- **Состояние (State)** — текущее изменяемое состояние.
- **Память (Memory)** — долговременная информационная организация.
- **История (History)** — причинная линия изменений.
- **Контекст (Context)** — оперативный срез для модели.
- **Среда выполнения (Runtime)** — механизм исполнения.
- **Хост (Host)** — конкретная вычислительная/API-среда.
- **Модель (Model)** — когнитивный вычислительный компонент.

Ключевой инвариант:

~~~text
ГЕНОМ ≠ СОСТОЯНИЕ ≠ ПАМЯТЬ ≠ ИСТОРИЯ ≠ КОНТЕКСТ ≠ СРЕДА ВЫПОЛНЕНИЯ ≠ ХОСТ
~~~

## Первый инженерный рубеж

До большой агентной системы необходимо получить минимальную среду выполнения:

- `GenomeLoader`;
- контрольная сумма и происхождение;
- `StateStore`;
- `MemoryStore`;
- `HistoryStore`;
- `ContextCompiler`;
- один `HostAdapter`;
- один `ModelAdapter`;
- `Validator`;
- `SessionManager`;
- сохранение данных;
- `EvaluationRunner`.

Названия компонентов здесь сохранены как технические идентификаторы; их описания и документация должны оставаться русскоязычными.

## Важное ограничение

Репозиторий не утверждает наличие сознания или субъективного опыта как научно установленного факта. Это должно быть отделено от инженерно проверяемых свойств среды выполнения.
