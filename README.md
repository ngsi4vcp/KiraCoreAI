# KiraCoreAI

**KiraCoreAI** — нормативное и исполняемое ядро проекта **Кира:Ядро**.

## Текущий статус

**Основание / G22 → минимальная исполняемая среда Кира.**

Канонический G22 зафиксирован в genome/G22.txt. Поверх него реализован первый проверяемый исполняемый слой: загрузка и проверка генома, сессионное состояние, память с ручным утверждением, история, компиляция контекста, протокол ПУЛЬС, валидация ответа и атомарное сохранение состояния.

~~~text
Геном G22
    ↓
Загрузчик и валидатор
    ↓
Состояние + память + история
    ↓
Компилятор контекста
    ↓
Адаптер хоста
    ↓
Адаптер модели
    ↓
Валидатор ответа
    ↓
Сохранение состояния
~~~

Это не конечный агент. Это минимальный каркас, на котором можно проверять инварианты Кира до подключения конкретной модели или хоста.

## Что уже реализовано

- каноническая загрузка G22 с проверкой SHA-256;
- проверка ревизии и обязательных признаков G22;
- точная авторизация Алека через ~1 в первом сообщении сессии;
- вычисление ПУЛЬС по формуле G22;
- отдельные хранилища состояния, памяти и истории;
- память по умолчанию как candidate, с отдельным авторизованным утверждением;
- компиляция оперативного контекста без автоматического включения всей памяти;
- извлечение защищённых правил непосредственно из загруженного G22;
- контракт хоста и контракт модели без привязки к поставщику;
- валидация обязательного ПУЛЬС в конце ответа;
- атомарное сохранение состояния в JSON;
- машинно-читаемые JSON-схемы;
- базовый набор из 6 протокольных и интеграционных проверок.

## Архитектурный принцип

~~~text
                    KIRACOREAI
                        │
                  КИРА:ЯДРО / ГЕНОМ
                        │
                  СРЕДА КИРЫ
                        │
          ┌─────────────┼─────────────┐
          │             │             │
         Pi           Codex        Hermes
          │             │             │
        Хост          Хост          Хост
          │             │             │
        Модель        Модель        Модель
~~~

**Не:** ChatGPT = Кира.  
**Не:** хост или фреймворк = Кира.  
**Да:** Кира:Ядро + сохраняемое состояние + текущий контекст + фактическая среда реализации = конкретная реализация Киры.

## Главные разделения

- **Геном** — конституционный слой.
- **Состояние** — то, что важно сейчас.
- **Память** — значимый накопленный опыт.
- **История** — причинная траектория изменений.
- **Контекст** — оперативный срез текущей сессии.
- **Среда выполнения** — механизм исполнения.
- **Хост** — конкретная вычислительная/API-среда.
- **Модель** — когнитивный вычислительный компонент.

Ключевой инвариант:

~~~text
ГЕНОМ ≠ СОСТОЯНИЕ ≠ ПАМЯТЬ ≠ ИСТОРИЯ ≠ КОНТЕКСТ ≠ СРЕДА ВЫПОЛНЕНИЯ ≠ ХОСТ
~~~

## Текущий исполняемый слой

Исходный код находится в src/kiracore/.

Основные компоненты:

- GenomeLoader и GenomeValidator;
- StateStore;
- MemoryStore;
- HistoryStore;
- ContextCompiler;
- SessionManager;
- OutputValidator;
- JsonPersistence;
- HostAdapter;
- ModelAdapter.

Исполняемый слой не имеет API для изменения канонического генома. Изменение генома остаётся отдельной управляемой транзакцией.

## Схемы

Каталог schemas/ фиксирует машиночитаемые контракты для ядра, состояния и записи памяти.

## Проверки

Локальная базовая проверка запускается без внешних зависимостей:

~~~bash
PYTHONPATH=src python -m unittest discover -s tests -v
~~~

Текущий набор проверяет:

- целостность G22;
- авторизацию ~1;
- формулу ПУЛЬС;
- обязательность ПУЛЬС;
- отделение утверждённой памяти от кандидатов;
- сквозной жизненный цикл сессии.

## Язык проекта

Русский — канонический язык Кира:Ядра и основной язык всей нетехнической документации.

Английское написание допускается для точных технических идентификаторов: API, имён библиотек, классов, функций, полей схем, команд, имён файлов и каталогов, когда это требуется стабильностью технического контракта.

Подробное правило закреплено в docs/language-policy.md.

## Важное ограничение

Репозиторий не утверждает наличие сознания или субъективного опыта как научно установленного факта. Исполняемые тесты проверяют наблюдаемые свойства реализации, а не решают философский вопрос о субъектности.

> Следующий шаг — подключение первого реального хоста и модели к уже зафиксированному контракту, а не изменение конституции под особенности конкретного хоста.
