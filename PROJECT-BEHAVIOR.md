# Целевое поведение KiraCoreAI

Этот документ описывает ожидаемый итоговый результат, а не текущее состояние.

## Сквозной сценарий

Пользователь запускает приложение → Core загружает и проверяет GENOME → восстанавливает требуемые состояние/сессию/разговор/память → выбирается модель → запрос проходит единый ModelRequest/ModelResponse контракт → runtime валидирует результат → формирует ПУЛЬС → сохраняет результат через канонический persistence boundary → приложение может восстановить сессию после restart.

## Семантические инварианты

- GENOME не смешивается с состоянием.
- История не является разговором.
- Контекст является производным.
- Модель не утверждает долговременную память автоматически.
- Candidate и approved — разные состояния.
- Неопределённый model-call не превращается в успешный результат.
- ПУЛЬС формирует runtime.
- Платформенный host не получает права изменить смысл Core.
- Секреты и authority material не проникают в модельный контекст.

## Целевые платформенные различия

UI, storage API, OS lifecycle, secure storage, background execution и release packaging могут отличаться.
Семантика Core и наблюдаемое поведение сохраняются.

## Промежуточные результаты

Промежуточная реализация может быть неполной и содержать известные ограничения.
Это не противоречит целевому поведению, пока ограничения явно отражены в фактическом `STATUS` и соответствуют текущему этапу плана.
