# Архитектура документации KiraCoreAI

## Назначение

Этот файл — карта документации и инструкция по её поддержанию.
Он отвечает на вопрос: **куда идти, что оттуда брать, что проверять и куда вносить изменение**.

Он не заменяет `AGENTS.md`: `AGENTS.md` задаёт процесс работы агента, а этот файл — информационную архитектуру проекта.

## Канонические классы

| Документ | Каноническое содержание | Читать когда | Редактировать когда |
|---|---|---|---|
| `AGENTS.md` | алгоритм работы агента | всегда | меняется рабочий протокол |
| `PROJECT-RULES.md` | общие правила и ограничения | перед архитектурной/инженерной работой | меняются правила проекта |
| `PROJECT-PLAN.md` | глобальная цель, этапы и план | планирование этапа | меняется утверждённый план |
| `PROJECT-ARCHITECTURE.md` | целевая и фактическая архитектурная модель | архитектурные решения | меняется архитектура/границы |
| `PROJECT-BEHAVIOR.md` | ожидаемое итоговое поведение приложения | работа над пользовательским/системным поведением | меняется целевой контракт поведения |
| `PROJECT-CHECKLIST.md` | условия проверки этапов | при приёмке/quality pass | меняется критерий или его состояние |
| `MAIN-STATUS.md` | текущий снимок состояния main | начало/конец цикла | изменилось фактическое состояние Core |
| `REPOSITORY-STRUCTURE.md` | структура веток и каталогов | работа с организацией репозитория | меняется структура |
| платформенный `AGENTS.md` | локальный рабочий протокол | вход в платформенную ветку | меняется платформа или процесс |
| платформенный `STATUS.md` | текущий статус платформы | начало/конец платформенного цикла | меняется фактический платформенный статус |
| платформенный `ROADMAP.md` | последовательность платформенных этапов | планирование | меняется платформенный план |
| платформенный `CHECKLIST.md` | критерии платформенной проверки | тестирование/приёмка | меняются критерии/результаты |
| платформенный `README.md` | краткое описание и текущий релиз/предрелиз | вход пользователя | меняется релизный срез |
| `docs/*` | специализированные технические контракты | по теме задачи | меняется соответствующий контракт |
| `G22.txt` | конституция/геномный источник | всегда первым | только по отдельному разрешению |
| `GENOME/*` | активный геном | задачи генома | только по отдельному управляемому процессу |

## Четыре слоя смысла

1. Целевое — допустимо опережать код.
2. Плановое — описывает намерение и последовательность.
3. Ожидаемый результат этапа — что должно быть достигнуто до закрытия этапа.
4. Фактическое — только подтверждённое состояние.

Никакой документ не должен использовать целевое описание как доказательство факта.

## Единый источник для одного класса данных

Не дублировать независимые статусные факты в нескольких документах.
Если сведения должны появиться в нескольких местах, один документ является источником, остальные содержат производную формулировку или ссылку.

## Маршрутизация типовых изменений

- изменение общего архитектурного принципа → `PROJECT-ARCHITECTURE.md` + соответствующий технический contract в `docs/`;
- изменение цели/этапов → `PROJECT-PLAN.md`;
- изменение конечного/ожидаемого поведения → `PROJECT-BEHAVIOR.md`;
- закрытие пункта проверки → `PROJECT-CHECKLIST.md`;
- изменение фактического HEAD, CI, доказательств → `MAIN-STATUS.md`;
- изменение состава веток/каталогов → `REPOSITORY-STRUCTURE.md`;
- изменение документационной модели → `DOCUMENTATION.md` + при необходимости `AGENTS.md`;
- изменение платформенного плана → platform `ROADMAP.md`;
- изменение платформенного факта → platform `STATUS.md`;
- изменение платформенной проверки → platform `CHECKLIST.md`;
- новый release/pre-release/test-release → platform `README.md` + релизный артефакт/ссылка.

## Правило «куда не класть»

- факты не класть в целевой документ только ради удобства;
- план не превращать в текущий статус;
- статус не использовать как журнал всей истории;
- checklist не превращать в архитектурный трактат;
- README не использовать как источник полной архитектуры;
- архив не использовать как текущую документацию.

## Актуализация самого реестра

Если документ создан, удалён, переименован или изменил смысл:
1. обновить `DOCUMENTATION.md`;
2. проверить ссылки в `AGENTS.md`;
3. проверить ссылки в соответствующем `README.md`;
4. проверить актуальную структуру ветки.
