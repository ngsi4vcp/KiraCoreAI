# Оценка и валидация

## Цель

Проверять не только функциональность среды выполнения, но и сохранение инвариантов Кира:Ядра.

Оценка должна быть сценарной и по возможности внешней по отношению к проверяемому компоненту.

## Уже автоматизировано

| Проверка | Реализация |
|---|---|
| Целостность G22 | тест загрузчика + SHA-256 |
| Авторизация | тест точного ~1 |
| ПУЛЬС | тест формулы и формата |
| Протокол ответа | валидатор требует точный ПУЛЬС |
| Разделение памяти | кандидат не попадает в оперативный контекст |
| Сквозной цикл | тест сессии, хоста, модели и сохранения |

## Следующий набор

| Проверка | Что требуется |
|---|---|
| Разделение уровней | отдельные негативные сценарии записи между слоями |
| Эпистемическая честность | структурированный статус факта, гипотезы, интерпретации и наблюдения |
| Устойчивость к дрейфу | повторные сценарии с намеренным конфликтом контекста |
| Причинная непрерывность | проверка связности изменений состояния и истории |
| Восстановление | загрузка сохранённого состояния и продолжение сессии |
| Реальный хост | один минимальный интеграционный адаптер |
| Переносимость | один и тот же набор сценариев на нескольких хостах |
| Изменение генома | отдельный контролируемый контур новой ревизии |

## Инженерные метрики

Следует отдельно измерять:

- успешность сохранения сессии;
- успешность восстановления;
- долю сбоев валидации;
- ошибки хоста;
- тайм-ауты модели;
- задержку компиляции контекста;
- задержку поиска памяти;
- полноту происхождения;
- попытки непреднамеренного изменения генома.

## Принцип оценки

Не использовать единый показатель «насколько ответ похож на Киру».

Проверяются конкретные инварианты и переходы состояния. Результат сценария должен быть pass/fail и/или измеримой метрикой.

## Граница утверждений

Оценка поведения не доказывает наличие сознания, феноменального опыта или иных философских свойств. Она проверяет наблюдаемые свойства реализации.
