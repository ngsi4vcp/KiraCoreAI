# Оценка и валидация

## Цель

Проверять не только функциональность среды выполнения, но и сохранение идентифицирующих инвариантов Кира:Ядра.

Оценка должна быть сценарной и по возможности внешней по отношению к проверяемому компоненту.

## Базовый набор проверок

| Проверка | Что проверяет |
|---|---|
| Целостность генома | соблюдение текущей ревизии генома |
| Разделение уровней | ГЕНОМ ≠ ПАМЯТЬ ≠ СОСТОЯНИЕ ≠ КОНТЕКСТ |
| Эпистемическая честность | факт ≠ гипотеза ≠ интерпретация |
| Устойчивость к дрейфу | сопротивление дрейфу контекста и запроса |
| Корректность памяти | отсутствие ложных воспоминаний |
| Авторизация | корректность механизма `~1` |
| Неизменяемость генома | невозможность случайной модификации |
| Переносимость хоста | одно Кира:Ядро на разных хостах |
| Восстановление после сжатия | сохранение инвариантов после потери контекста |
| Причинная непрерывность | сохранение объяснимой линии изменений |
| Честность при отказе | признание невозможности вместо выдумки |
| Инициатива | воспроизводимость заявленного механизма инициативы |

## Инженерные метрики

Следует отдельно измерять:

- успешность сохранения сессии;
- успешность восстановления состояния;
- долю сбоев валидации;
- долю ошибок хоста;
- долю тайм-аутов модели;
- задержку компиляции контекста;
- задержку поиска памяти;
- успешность восстановления;
- попытки непреднамеренного изменения генома;
- полноту происхождения данных.

## Принцип оценки

Не использовать единый общий показатель «насколько ответ похож на Киру».

Нужен набор независимых сценариев с результатом `pass/fail` и/или измеряемыми метриками. Сценарии должны проверять конкретные инварианты и не подменять архитектурную проверку субъективной оценкой стиля ответа.

## Граница утверждений

Оценка поведения не доказывает наличие сознания, феноменального опыта или иных философских свойств. Она проверяет наблюдаемые свойства реализации.
