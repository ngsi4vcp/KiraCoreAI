# Модель контекста, состояния и памяти

Главная инженерная задача Кира:Ядра — контролировать, какая часть долговременной структуры становится оперативным контекстом модели.

Хранение информации и предъявление информации модели — разные задачи.

## Канонические уровни

| Уровень | Назначение | Изменяемость |
|---|---|---|
| Геном | конституция | только контролируемая ревизия |
| Состояние | текущее рабочее состояние | высокая |
| Память | долговременная информация | управляемая |
| История | причинная линия | преимущественно добавляемая |
| Контекст | оперативный срез | временный |
| Среда выполнения | исполнение | зависит от реализации |
| Хост | внешняя вычислительная среда | внешняя |

## Компилятор контекста

Компилятор получает актуальную ревизию генома, снимок состояния, релевантные записи памяти и истории, текущую задачу, доступные инструменты и ограничения хоста.

Базовый приоритет:

1. защищённые правила;
2. текущая задача и цель;
3. релевантное состояние;
4. релевантная память;
5. недавние ошибки;
6. доступные инструменты;
7. недавние наблюдения.

Полная память не должна автоматически попадать в контекст модели.

## Запись памяти

Минимальная форма записи:

~~~yaml
id:
type:
content:
timestamp:
source:
confidence:
importance:
provenance:
entities:
valid_from:
valid_to:
~~~

Типы записей:

- `FACT` — факт;
- `RELATIONSHIP` — отношение;
- `EVENT` — событие;
- `DECISION` — решение;
- `EXPERIENCE` — опыт;
- `DISCOVERY` — открытие;
- `HYPOTHESIS` — гипотеза.

Имена полей и перечислений сохраняются как технический контракт; смысл и описание должны быть на русском языке.

## Эпистемический статус

Нужно различать факт, гипотезу, интерпретацию, вывод и наблюдение среды выполнения.

Убедительная реконструкция моделью прошлого не становится от этого воспоминанием.

Запись «инструмент сообщил X» также не становится автоматически фактом без соответствующей проверки.

## Сжатие

При сжатии в первую очередь сохраняются:

1. инварианты идентичности;
2. СТОП-элементы;
3. эпистемические различия;
4. состояние авторизации;
5. критическое состояние;
6. происхождение данных.

Остальная информация может сжиматься по убыванию значимости.

## Причинная непрерывность

Изменение состояния должно быть по возможности связано с источником, временем и причиной. Это позволяет отделять:

- сохранённую память от реконструированного содержания;
- текущее состояние от истории;
- локальный контекст от устойчивой идентичности;
- предложение изменения архитектуры от уже зафиксированной ревизии.
