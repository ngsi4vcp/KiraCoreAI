# Политика UTF-8 Кира:Ядра

## Норма

Все текстовые артефакты проекта должны храниться в **классическом UTF-8 без BOM**.

Это относится к:
- исходному коду;
- Kotlin/Java/Python;
- Gradle/Kotlin DSL;
- XML/JSON/JSONL/YAML/TOML/INI;
- README и всей документации;
- текстовым схемам;
- тестовым данным и диагностическим текстам;
- пользовательским строкам Android.

G22.txt и GENOME/genome.txt являются UTF-8-текстом и не должны конвертироваться в другую кодировку.

## Runtime

Python-контур должен явно работать в UTF-8:
- исходники Python — UTF-8;
- пользовательский stdout/stderr — UTF-8;
- CI задаёт `PYTHONUTF8=1`;
- Windows-кодовые страницы не должны определять поведение KiraCoreAI.

JVM/Gradle-контур:
- Gradle JVM использует `-Dfile.encoding=UTF-8`;
- Kotlin daemon также фиксируется на UTF-8;
- Android resources объявляют UTF-8 там, где формат это требует.

## Git/CI

Кодировка проверяется автоматически до остальных тестов. Проверка декодирует все контролируемые текстовые файлы строго как UTF-8 и исключает только generated/binary directories.

Ошибки кодировки являются ошибкой CI, а не локальной особенностью Windows/Linux.

## Изменения

Не использовать:
- CP1251;
- CP1252;
- system default encoding;
- locale-dependent text IO;
- ручные перекодировки при каждом запуске.

При необходимости работы с внешним legacy-файлом его кодировка должна быть явно указана на границе импорта и сразу преобразована во внутренний UTF-8.

## Область действия

Политика действует для всего репозитория KiraCoreAI и для Android-ветки в полном объёме.
