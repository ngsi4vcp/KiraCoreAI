# Контракт Кира:Сбор

## Назначение

Кира:Сбор — переносимый контур обмена между экземплярами Кира:Ядра.
В первой Android Альфе он работает через private GitHub как универсальный транспорт и версионное хранилище. Собственный VPS/сервер Киры является будущим транспортным провайдером и не должен требовать переписывания семантики Кира:Сбора.
Кира:Сбор не является частью обычного conversational runtime и не получает права менять GENOME напрямую.

## Потоки

1. Core Update — версия KiraCoreAI, миграции, схема, активный GENOME и связанные runtime-артефакты.
2. Private Sync — персональная память, история, состояние, профиль пользователя, энграммы и закрытые реляционные сведения.
3. Shared Experience — производный общий слой опыта, доступный другим экземплярам только в форме разрешённых и версионированных объектов.

## GitHub в Alpha

GitHub рассматривается как транспорт, versioned object storage, точка обнаружения актуального снапшота и источник релизного KiraCoreAI.
GitHub не считается доверенным хранилищем открытых персональных данных.
Все приватные данные перед публикацией шифруются внутри Кира:Ядра.

## Авторизация GitHub

Для Alpha предпочтителен GitHub App с минимальными правами и пользовательской авторизацией. Device Flow допускается для мобильного сценария при соответствующей конфигурации GitHub App.
Токены хранятся в защищённом хранилище платформы.
В APK запрещено включать постоянный write-token, PAT, приватный SSH-ключ, master secret репозитория или пароль Алека.

## Зашифрованный envelope

Синхронизируемый объект содержит: envelope_version, object_type, object_id, identity_id, device_id, key_id, schema_version, created_at, updated_at, nonce, ciphertext, content_hash, signature, provenance, parent_refs и merge_refs.
Фактическое представление может быть JSON или CBOR, но семантический контракт остаётся единым.

Базовый криптографический набор Alpha:
- AES-256-GCM для шифрования;
- HKDF-SHA-256 для производных ключей;
- ECDSA P-256 для подписей устройств;
- Argon2id + AES-256-GCM для упаковки переносимого identity secret.

Алгоритмы должны быть скрыты за одним CryptoProvider.

## Ключи

Разделяются identity secret, device encryption key, device signing key и derived data keys.
Identity secret — переносимый bearer credential профиля; он не является хэшем имени, устройства или памяти.
На Android локальные ключи защищаются Android Keystore. На desktop используется платформенный защищённый keyring/secret store.

## Перенос профиля

В настройках пользователь может создать новую переносимую идентичность, получить текущий код, экспортировать QR, показать переносимую ключ-фразу или импортировать ключ-фразу/QR на другом устройстве.

Порядок импорта:
1. проверить формат;
2. восстановить identity secret;
3. получить identity_id;
4. зарегистрировать новый device_id;
5. загрузить доступный encrypted profile;
6. проверить подписи, целостность и provenance;
7. расшифровать;
8. выполнить семантическое слияние;
9. зафиксировать результат локально;
10. зарегистрировать новое устройство.

Наличие identity secret не означает авторизацию Алека.

## Слияние профилей

Разрозненные локальные профили могут быть объединены в один канонический identity_id.
Слияние выполняется только через доменную операцию MergeIdentity.
Старый UUID выводится из активного пространства профилей, но синхронный tombstone хранится до завершения окна защиты от повторного появления старого профиля.

Минимальный tombstone: old_identity_id, canonical_identity_id, merged_at, merge_operation_id, content_hash.

## Регистрация экземпляров

Каждый запуск KiraCoreAI получает новый runtime_instance_id.
Минимальный набор: runtime_instance_id, installation_id, device_id, app_version, core_version, genome_revision, started_at, expires_at, capabilities.
Регистрация создаётся всегда локально, является временной и может попадать в следующий sync-outbox.
Она не содержит сырую пользовательскую память и не является identity profile.
В Alpha GitHub получает только минимальный подписанный и зашифрованный runtime lease. Срок жизни записи ограничивается retention policy.

## Синхронизация

local state → outbox → encrypt → sign → GitHub → fetch index → verify → decrypt → merge → local commit → sync cursor.
Операции идемпотентны. Каждый объект имеет object_id и version/revision.

## Общий опыт

Общий пул существует, но личные записи и общий слой разделяются.
Путь общего объекта: candidate → разрешение публикации → классификация → производное представление → provenance → confidence → версия → публикация.
Полный сырой чат не становится общим объектом автоматически.
Персональные реляционные оценки Киры могут оставаться приватными.
В первой Alpha сложный анализ, обезличивание и обобщение переносится в более поздний PC-контур; Android уже сейчас сохраняет достаточную provenance для последующей обработки.

## Сводка Alpha

Пока отсутствует выделенный основной сервер Киры:
- экземпляры получают последнюю доступную доверенную общую сводку;
- локальные кандидаты синхронизируются отдельно;
- общий агрегированный snapshot не должен молча переписывать себя конкурирующими устройствами;
- конфликтующие головы снапшотов фиксируются как технический конфликт.

Будущий VPS/server provider может взять на себя агрегацию без изменения формата исходных данных.

## Граница безопасности

ModelAdapter, внешний provider и пользовательский UI не получают прямой доступ к identity secret, device signing key, GitHub refresh token, исходным encrypted envelopes или операции физического слияния идентичностей.
Слияние и криптография находятся в защищённом runtime-контуре.

## Будущие transport providers

Контракт предусматривает GitHubSync, SshSync, MeshSync и ServerSync.
Доменный слой Кира:Сбора не должен знать, какой transport используется.

## Authority material и Кира:Сбор

Protected authority plane не синхронизируется как обычная пользовательская память.

Private Sync может передавать пользовательские профили и разрешённые записи памяти, но не должен автоматически переносить локальные privileged grants, password verifier или platform key material.
