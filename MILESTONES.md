# Контрольные точки проекта

## Назначение

Этот файл заменяет обязательную зависимость от Git-теги для внутренних контрольных точек проекта.

Каждая контрольная точка фиксируется как запись в Git и привязывается к **неизменяемый commit SHA**. SHA коммита является техническим якорем, а этот реестр хранит смысловую расшифровку: что именно зафиксировано, в какой ветке, с каким статусом и какими доказательствами.

Это не замена Git-историю и не разрешение считать непринятый этап принятым.

## Правила

1. Контрольная точка получает уникальный идентификатор.
2. Для неё указывается точный commit SHA.
3. Указывается ветка и дата фиксации.
4. Указывается статус из общей шкалы проекта.
5. Для принятия указывается конкретное доказательство/приёмка основание.
6. Если этап ещё не принят, запись прямо это отражает.
7. После публикации запись не переписывается задним числом; исправления оформляются новой контрольной записью.
8. При изменении архитектуры или документации реестр обновляется в `main`.
9. Платформенные контрольные точки могут ссылаться на commit SHA платформенной ветки.
10. Удаление branch ref не уничтожает контрольную точку, пока её commit SHA достижим через Git history или archive.

## Что этот механизм не делает

- не заменяет выпуски GitHub для публичных релизов;
- не превращает реализацию в принятие;
- не заменяет device acceptance;
- не создаёт криптографическую подпись автора;
- не должен использоваться для изменения исторических SHA.

Для публичных релизов по-прежнему используются GitHub Releases и соответствующие release-артефакты.
