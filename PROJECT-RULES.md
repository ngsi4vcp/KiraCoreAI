# Правила проекта KiraCoreAI

## Базовые принципы

- Истина важнее удобства.
- Фактическое состояние важнее устаревшего описания.
- Целевое состояние не выдаётся за реализованное.
- Причинность и Git-история сохраняются.
- Общая семантика принадлежит Core; платформа реализует host-specific слой.
- Русский — канонический язык проектной документации.
- G22/GENOME изменяются только управляемо и отдельно.
- Состояние, память, история, разговор, контекст и среда остаются раздельными доменами.

## Статусы

Единая шкала:

`ПЛАНИРУЕТСЯ → В РАЗРАБОТКЕ → РЕАЛИЗОВАНО → ПРОВЕРЕНО → ПРИНЯТО → ВЫПУЩЕНО`

Дополнительные состояния: `ЗАБЛОКИРОВАНО`, `ОТЛОЖЕНО`, `УСТАРЕЛО`, `ОТМЕНЕНО`.

Переход между статусами должен иметь соответствующее основание.

## Приёмка

Компиляция не равна приёмке.
Тест не равен приёмке.
Device evidence не отменяет contract tests.
Историческое доказательство не является текущим без сверки.

## Ветви

`main` — каноническая база Core.
Платформа не копирует общий Core как независимый проект.
После изменения Core рабочая платформа получает новую принятую версию Core и выполняет собственные интеграционные проверки.

## История

Старые ветви сначала инвентаризируются и архивируются.
Удаление ссылок на старые ветви производится только после итоговой проверки.
Контрольные точки и их доказательства сохраняются в `MILESTONES.md` и Git history.

## CI-ресурс

Core-проверки выполняются в `main`.
Платформенные ветки проверяют связку Core+Platform.
Не запускать параллельные полные проверки без причины.
